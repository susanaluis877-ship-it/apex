# 选择器和页面条件怎么挑

## 动作的目标（选择器）

`act` 用 `@引用` 时会自动挑一个在设备上验证过、唯一命中的选择器，并把它显示出来，大多数时候直接用它。自己挑时按这个顺序：

1. **资源 id**（`{"id": "slider"}`）：最稳，不受语言和文案变化影响。但 `a1`、`b2c` 这种混淆过的 id 每次发版都可能变，不要用。
2. **描述 desc**：图标按钮常只有描述（「返回」「添加」）。
3. **固定的文字 text**：按钮、菜单项、设置项的标题。
4. **组合**：单个条件命中多个时，加上 `className`、`clickable` 或另一个特征；列表里一排相同的按钮，用 `inside` 限定在含有某段文字的那一行里（`{"text": "领取", "inside": {"hasDescendant": {"text": "任务 A"}}}`）。
5. **点击落到可点击的祖先**：一行设置项通常是「整行可点击 + 里面的文字」，选里面的文字即可，`click` 会自动点到整行。
6. **最后才用坐标**：`tap` 按比例坐标（`xRatio`/`yRatio`）比像素坐标好一点，但换分辨率、换布局都会失效，交付时要说明。

避开：

- **会变的文字**：数字、时间、计数、余额（「1,234 积分」「已用 23 分钟」）。需要时用 `textMatches` / `descMatches` 把数字部分写成 `\d+`；判断滑块位置用 `progressAtLeast` / `progressAtMost`，判断开关状态用 `checked` 或 `stateDesc`。
- **只在某种状态下才有的文字**（「已关闭」「开启」）当定位用。
- **广告、推荐、消息流里的内容**。

不可见的虚拟节点（滚轮选择器的每一列、一些自绘控件）要加 `"visible": false`，否则选择器找不到它们。

**「不等于」**：选择器没有 not，用正则的负向前瞻，例如「名称不是 Apex 的那一行」：`{"textMatches": "(?!(.* \\| )?Apex$).*"}`。页面级的「没有某个节点」用 matcher 的 `not`：`{"not": {"has": {...}}}`。

`act` / `suggest` 的选择器只保证在当前可见的节点里唯一。提示「另有 N 个不可见的同样节点」时（同一个 Activity 的其他标签页里也有同 id 的按钮），换成描述、文字或用 `inside` 限定。

## 页面条件（状态的 match）

页面条件回答「现在是不是这个页面」。好的条件：

- **独有**：只有这个页面有。`features P3` 会列出本次探索到过的其他页面都没有的特征。
- **稳定**：每次进来都有，不依赖数据、时间、滚动位置。标题和固定的标签文字最好；列表里的内容会随滚动消失，不要用。
- **候选状态之间互斥**：同一个 `next` 里的几个状态不能同时匹配同一个页面（`check` 的 `ambiguous` / `wrong-winner` 会报出来）。一定要靠顺序区分时，把更具体的放前面。
- **带上 `package`**：防止别的应用里同名文字误匹配。

弹窗盖住页面时，系统可能只上报弹窗那一个窗口（下面的页面完全看不到），所以：

- 状态条件不要指望「页面 + 弹窗」同时可见。
- 拦截器条件要足够具体（弹窗的包名、id、按钮文字），不要匹配到正常页面——`check` 的 `interceptor-on-state-page` 会报出来。

区分「操作前」和「操作后」：例如点「保存」后列表里出现新的一条，成功状态的条件要能区分操作前的列表（新条目独有的内容），否则一进来就误判成功。

多选后批量操作（删除、移动）前，条件要核对**选中的是哪一项**，不能只看「已选择 1 项」这类标题：用 `{"hasDescendant": [{"text": "目标"}, {"checked": true}]}` 确认目标已选中，再用 `not` 排除「其他行也被选中」。全选时标题可能变成「已选择全部项」之类的写法。

## 用 check 验证

探索时到过的页面都存成了样本。写完流程后：

```
check flow.json --label P1=home P2=display P3=done
```

- `expected-mismatch`：这个页面的状态没匹配上自己的样本 → 条件写错了。
- `wrong-winner` / `ambiguous`：多个候选匹配同一个样本 → 让条件互斥，或调整 `next` 顺序。
- `interceptor-on-state-page`：拦截器会在正常页面误触发 → 收紧拦截器条件。
- `too-broad`：某个状态匹配所有样本 → 条件太宽。
- `unmatched`：样本没有任何状态匹配 → 漏了状态，或者它只是过渡页（可以忽略）。
